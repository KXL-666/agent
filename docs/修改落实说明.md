# 四项修改建议落实说明

## 交付物质量

保留已有内容生成、扩写和固定排版的改进，进一步补强：

- 自检重生成使用独立临时文件，失败不会覆盖首轮可用文件；重新生成后再次检查。
- 提示词要求基于用户素材，标记假设和模拟数据，不虚构统计、来源、测试执行结果。
- 过程产物内容保存上限从 2,000 字提高到 16,000 字，减少整合成品时的信息丢失。
- 重试接口保留真实质检失败原因，代码包重新打包也重新检查语法。
- 未通过验收或成品质检时，迭代结束提示「交付待修正」，不弹出成功交付提示。

## 敏捷流程

计划任务增加用户故事、业务优先级、故事点、验收标准，持久化到 SQLite；旧数据库自动补列。

任务流转为：待分派 → 待开发 → 待测试 → 待评审 → 通过；缺陷或评审拒绝进入返工。返工次数有明确上限，不能无限循环或在未通过时发布。

任务中心展示迭代目标、计划/完成/剩余故事点和状态列，任务详情展示用户故事与验收标准。旧任务缺少估点时标记未估点，不虚构历史数据。

测试环节获得任务的验收条件。自动语法检查仅证明语法正确；模型判断不等同于真实功能测试，仍应结合具体项目执行功能验收。

## 产物归档

```text
backend/
  deliverables/
    YYYY-MM-DD/项目编号/最终成品
  workspace/
    code/项目编号/开发源码
    files/唯一编号/过程文档或下载缓存
    legacy/旧过程文件
    backups/归档迁移前的数据库备份
```

日期使用北京时间。独立生成产物归到当前项目，无项目时使用「独立生成」目录。最终交付版本使用唯一文件名，避免并发覆盖。

服务启动自动运行 `archive_layout.migrate()`：先更新产物文件引用，再将旧文件移到过程区，保留旧文件标识的解析能力。迁移可重复运行，文件冲突时保留原文件并报错。备份导出/导入包含 workspace，过程文件可继续查看。

## AI 对话

- 各成员独立请求、独立中断、独立输入草稿和附件，切换成员不会禁用其他成员的发送按钮。
- 请求状态保存在共享聊天 store，切换页面后仍能查看正在回复的成员。
- 流式回复绑定发出请求的成员，交错返回不会串入当前选中的成员。
- 移除固定 80 字限制，增加回复 token 上限，注入实时需求、任务、阶段与产物状态。
- 当前时间/日期问题读取北京时间，不调用模型；模型不可用时明确告知连接问题，避免模板回答假装已执行任务。
- Sprint 规划、测试、评审等同步模型调用移至工作线程，避免阻塞服务处理聊天和其他请求。

## 验证范围

后端回归覆盖归档隔离、旧文件迁移、路径穿越防护、计划持久化、质检重试、当前时间、并发流式聊天、评审返工与次数上限。前端回归覆盖成员请求与聊天记录隔离、独立中断。另执行生产构建、ESLint 和实际浏览器检查。

回归使用本地隔离数据及模拟模型；未批量调用已配置的外部模型生成新交付物。因此真实交付内容质量还取决于模型能力和输入素材，需要按具体需求验收。

本地历史数据核查：11 条已有文件引用在迁移后可正常读取；另有 12 条历史记录的原文件此前已缺失，对照迁移前数据库备份确认这些记录未被本次迁移修改。没有用摘要伪造成原文件。
