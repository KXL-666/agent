# 真实用户可用性测试方案（待招募参与者）

## 测试目标

观察目标用户能否独立完成「认识项目 → 发起任务 → 判断进度与费用 → 找到并验收成品」。本文件是测试脚本，不包含真人测试结论。

## 参与者与环境

- 招募 3–5 位此前未使用过本项目的目标用户，建议覆盖需要生成文档或代码的用户，以及毕业设计评审/同学。
- 每人独立测试约 30–35 分钟（手机端项目可选）。主持人只读任务说明，不提示按钮位置；参与者边操作边说出自己的判断。
- 使用隔离的数据副本或独立测试环境。开始前记录当前 Sprint 和产物数量；测试结束后保留记录，不在用户现有数据上清理。
- 默认用演示模式完成流程。真实模型任务只在参与者理解费用并且测试方设好预算上限后进行。
- 录屏、收集语音或保存参与者个人资料前，先征得其同意。测试记录用编号代替姓名。

## 任务脚本

按顺序给参与者看每一条任务，完成后再给下一条。主持人记录点击路径、耗时、求助、误解和原话。

1. **首次认识（3 分钟）**：打开首页，不解释产品。请说出这个项目能帮你做什么、你认为下一步该点哪里。
2. **零费用体验（5 分钟）**：在不花模型费用的情况下，让团队完成一次示例任务。请在开始前说出你预计会得到什么文件。
3. **查看进度与费用（4 分钟）**：找出当前任务是否结束、完成了多少、这次花费多少。请说明你如何区分本次费用和历史累计费用。
4. **寻找成品（5 分钟）**：找到最终交付的 Word 文件，预览内容并指出哪里可以下载。请判断它是真实模型生成还是演示内容，以及你依据的界面信息。
5. **查验任务（4 分钟）**：找到一个已完成的子任务，查看其完成依据或验收条件；如果结果不符合要求，说出你会从哪里提出修改。
6. **自由反馈（3 分钟）**：说出最困惑的一处、最有价值的一处，以及你愿不愿意用它完成自己的真实任务，原因是什么。
7. **资料定位（4 分钟）**：上传一份长文档，搜索主持人指定的后半部分事实，指出命中的文件与页码/片段；不得凭模型生成的文字猜测出处。
8. **计划核对（3 分钟）**：选择文件任务路线，预览执行计划，指出输入资料、交付类型、保存位置、费用上限和数据会发往何处；修改一项后确认计划随之更新，但不要启动付费任务。
9. **手机端操作（可选，3 分钟）**：在可信局域网使用手机访问入口，登录后找到任务进度和产物；在测试 Sprint 中执行暂停与继续，观察电脑端状态是否同步。

## 分析与建议规则

- 优先处理阻止参与者完成任务、误导费用判断或误认演示内容为真实交付的问题。
- 同一问题若至少 2 位参与者独立遇到，列为共性问题；仅 1 位遇到时结合操作录像和界面证据判断。
- 最终建议附每项问题的参与者人数、任务完成情况、原话或行为证据，再给改动方案和优先级。
- 不把开发者自测、代码检查或模拟用户评价写成真人测试结果。
