# 模拟用户视角走查（2026-10-23）

本评估由开发环境中的实际界面操作与代码核对完成，**没有真人参与者**；不包含任务成功率、满意度或用户原话。两种角色是分析视角，不是虚构的受访者。

## 走查角色与任务

| 视角 | 想完成的事 | 实际走查路径 |
| --- | --- | --- |
| 实际使用者 | 低成本试用、提出需求、确认进度与费用、验收下载文件 | 首页 → 新建任务弹窗 → 任务中心 → 产物中心 → 展开成品 |
| 毕设评审/同学 | 快速理解创新点、看清真实与演示能力、验证任务和产物可追溯 | 首页 → 演示 Sprint 状态 → 任务中心 → 产物中心 |

## 观察与建议（按优先级）

### P0：本次费用与累计费用容易混淆

当前演示 Sprint 顶部显示预计花费 `¥0.000`，产物中心同屏展示「累计花费 `¥1.6159`」。两个数字都成立，但作用范围不够醒目。建议固定标注「本次 Sprint 花费」和「所有历史任务累计花费」，并在用量明细默认展示本次数据。验收时让未看说明的使用者准确说出两个数字的含义。

### P0：演示与真实生成需要贯穿交付流程

新建任务弹窗已有演示按钮，需求、文件标题也标记了演示，但产物中心同时写「最终交付物与真实文件」，容易把“文件确实可下载”和“内容由真实模型生成”混为一谈。建议在产物卡上分别显示「生成方式：脚本演示/真实模型/兜底模板」和「文件状态：可预览/可下载/质检未通过」。避免只通过标题中的“演示”二字辨认。

### P1：交付物的主要操作需要更容易发现

产物列表默认只显示标题、扩展名和时间。实际点击标题行后才出现预览、下载、修改。建议最终成品卡片默认展示「预览」「下载」两个主操作；展开后保留版本、重试、编辑等次级操作。

### P1：进度指标语义不一致

当前演示 Sprint 顶部显示 4/4、100% 完成，任务中心又显示计划/通过/剩余故事点均为 0，并提示 4 项未估点。建议演示任务也提供故事点，或在未估点场景隐藏故事点进度、改显示「已通过任务 4/4」。顶部「今日任务」实际统计当前 Sprint 任务，应改为「本轮任务」。

### P1：首次进入的引导仍不够集中

新建任务、演示入口和配置入口都存在，但分布在底部工具栏、弹窗及智能体页。建议没有当前任务时，在办公室中央放「零费用体验」「创建真实任务」两个入口；真实任务入口先展示模型配置状态、费用上限和预期交付物。

### P2：键盘操作与控件语义需统一

任务中心部分卡片以 `article role=button` 实现但没有 `tabIndex` 或 Enter/Space 处理；产物标题行点击可展开，却以 `role=presentation` 呈现。工作空间切换也用可点击 `div`。建议统一使用原生 `button` 控件或补齐键盘和焦点行为。验收时只用键盘完成切换工作空间、打开任务和预览产物。

## 证据范围

- 本地 5173 前端、8000 后端可用；走查了首页、新建任务弹窗、任务中心、产物中心和演示成品展开。
- 观察使用现有演示 Sprint，没有启动付费模型任务，也没有招募参与者。
- 以上优先级是基于任务完成风险的专家判断。若未来有真人测试，可使用 `真实用户测试方案.md` 复核并调整。
