# 运行环境与质量实验

## 环境和执行边界

`npm run doctor` 是显式诊断，不安装软件、不启动模型任务。`ready` 仅说明该项探测通过；LibreOffice 版本可执行不保证文件转换成功，中文字体文件存在不保证每页排版正确。仍需真实成品渲染与验收。Docker 通过服务端信息探测，不能仅凭找到 CLI 宣称可运行测试。

默认 `python scripts/test-backend.py` 在临时数据库、临时模型配置、临时用量文件与生成目录中执行测试，模拟 Office 缺失。真实 Office 集成检查使用 `--with-office`，转换超时会终止本次转换的进程树。Linux CI 安装实际渲染环境并运行两组检查。

Office 转换在每次调用独立的暂存目录中完成；只有本次新生成的非空文件才会原子替换目标。即使转换进程返回成功，也不能拿目标目录中残留的旧 PDF 或表格当作本次结果。

后端采用同数据库单进程锁。取得锁后才迁移密钥、恢复最新任务快照，重复恢复不会叠加任务。正常关闭后端与异常重启都将未完成 Sprint 记为中断；用户主动停止保持“手动结束”。关闭时等待任务取消和用量收尾，不自动重放付费操作。仍未实现跨进程任务队列或多用户权限隔离。

## 重启后续跑

新建的协作模式 Sprint 使用 SQLite LangGraph 检查点，每个节点完成后同步保存。重启后进入任务中心，在“中断任务续跑”查看下一步骤、已记账费用与原预算，展开“查看并确认续跑”，勾选确认后点击“从检查点继续”。启动后端本身不会触发续跑或模型费用。旧版任务、快速模式和手动结束的任务不支持恢复。

已保存完成的节点不会重跑；中断时尚未保存完成的节点会重新执行，可能再次请求模型或生成文件，不保证外部调用只执行一次。原需求、附件上下文、执行模式、保存位置、预算、补充指示及取消/改派操作会保留。已收到模型响应的本任务用量独立入库，续跑沿用累计费用；服务商已计费但尚未返回用量的请求无法据此准确核算，应核对服务商账单。

后端代码或相关依赖版本变化、检查点不匹配、产物或代码源文件缺失/被修改、原执行进程仍存活、预算耗尽、模型配置不可用时拒绝续跑。修改后的文件应另开任务处理。检查点含任务上下文和附件内容，随其他业务数据保存在 `office.db`，备份应按敏感任务数据保管。

数据库备份使用 SQLite 在线备份 API，包含 WAL 中尚未合并的检查点。导入数据库备份后必须重启后端，再创建或恢复任务。恢复接口会校验检查点标识，重复请求通过请求标识去重。

- `GET /api/sprint/recoverable`：最近可检查的中断/失败任务及恢复条件。
- `GET /api/sprints/{id}/recovery`：指定任务的续跑计划。
- `POST /api/sprints/{id}/recover`：提交 `checkpoint_id` 和唯一 `request_id`，成功返回 202。

`python scripts/test-backend.py --pattern test_sprint_recovery.py` 使用模拟节点、真实 SQLite 和真实子进程强制终止验证恢复，不调用付费模型。

## 本地访问与密钥

浏览器来源校验保护本机 HTTP、WebSocket 与动作网关；手机代理仅在密码与原始来源通过后重写代理 Origin。它不能防御本机恶意程序，也不能替代身份认证。不要直接将后端暴露到公网。

Windows 密钥使用 DPAPI；macOS/Linux 使用原生 Keychain、Secret Service 或 KWallet，JSON 只保存不可预测的 `keyring:` 引用。安全存储不可用或加密失败时拒绝保存新密钥，不再回退明文，也不接受 plaintext/null 等非安全 keyring 后端。Linux 无桌面环境时需要可用且已解锁的 Secret Service / KWallet 会话。

`python scripts/check-runtime.py --require key_storage` 可将缺少安全存储视为诊断失败；它只检查后端是否可选，不读取实际密钥。写入时仍会执行回读确认。

更新配置会复用未变的密钥引用；新密钥只有在配置文件原子替换后才生效。保存失败清理新引用并保留旧文件；删除或轮换密钥时尽力清理旧引用，安全存储锁定时可能保留孤立条目。暂时无法解锁的旧引用不会因为修改成员姓名而被清空，可以显式清除或替换。历史明文配置会尝试迁移；迁移失败保留原文件并报告，不伪称已加密。

备份中的 DPAPI 密文依赖原 Windows 用户；非 Windows 的 keyring 引用不包含系统密钥存储本身。迁移到另一台机器或系统账户后需重新输入 API Key，不能把备份当作可移植密钥包。

技能包脚本仍以本机用户权限运行，只安装可信来源。

## 固定输入对比

以下命令会启动真实模型任务并计费用。执行前固定模型配置、服务商单价、字体、Office/Docker 版本与预算，确保没有其他任务运行。

```powershell
python scripts/run-quality-baseline.py --case W1 D1 P1 P2 X1 --execution-style quick --budget-yuan 1 --output-root work/baseline-quick
python scripts/run-quality-baseline.py --case W1 D1 P1 P2 X1 --execution-style collaborative --budget-yuan 1 --output-root work/baseline-team
# 汇总只读取已有 JSON，不联网、不执行任务：
python scripts/summarize-quality-baseline.py work/baseline-quick work/baseline-team --output work/baseline-summary.json
```

两种模式提交相同的原始需求和附件，并记录输入 SHA-256。汇总只把指纹一致的同题样本列入可比集合。旧记录没有指纹时仍可统计，但不能自动认定可比。代码 C1 不支持 quick，单独评测 collaborative，不能混入文件模式结论。

每组至少重复三轮，交替执行两种模式以降低时间和限流偏差。不要修改失败样本或只挑成功运行。每次执行使用新的时间戳目录；不要同时汇总同一 Sprint 的原始与刷新副本，脚本会拒绝重复 ID。

## 评价口径

- 通过率：必须有最终文件哈希、正式完成，且全部最终产物均为 passed，未降级。流程 completed 本身不代表成品通过。
- 失败、未验证、无成品分别计数；未验证不能计入通过。
- 耗时与成本按各组报告均值；缺少成本保持空值，不冒充零成本。费用为本地价格表估算，应与服务商账单另行核对。
- 仅有输入指纹一致还不足以证明实验完全可比，仍需人工记录模型配置和环境。样本量很小时不要声称统计显著。
- 隐去模式名称后进行人工盲评：事实准确性、需求覆盖、可编辑性、排版可读性、实际可运行性，各项 1–5 分，并记录问题位置。自动验收不能替代人工评分。

本轮代码改进未运行付费对照实验，不据此宣称六人协作提高了成品质量。
