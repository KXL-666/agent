# 生成质量基线样本 v1

本文件固定改造前后的测试输入与评分方法。每次运行使用同一需求、同一附件、同一模型配置；记录时间和用量。项目核心是六名智能体协作，因此每个任务都要分别记录**六人协作 Sprint**与明确选择的**快速生成**路线，不能拿快速生成结果代表六人协作。模型有随机性，因此对照要保存原文件并由人工匿名评分，不能只比较一次模型自评。

## 固定任务

以下内容为虚构测试素材，不涉及真实客户或密钥。运行时把“需求”原文作为用户输入；有“附件”的任务，把附带文本保存为 UTF-8 `.txt` 后上传。

### W1：简短通知（Word）

需求：`生成一份给研发与测试同事的 Word 通知，说明 11 月 4 日 14:00 至 16:00 进行接口联调，地点为线上会议室 A。前端在 11 月 3 日 18:00 前提交调用清单，后端在联调开始前准备测试环境，测试同事记录阻塞问题并在当日 20:00 前汇总。控制在一页，不要封面。`

重点：时间、责任人、截止时间无遗漏；一页、原生标题、通知语气；不增加不存在的会议链接。

### D1：有依据的分析报告（Word 与 PDF）

需求：`根据附件制作一份给项目负责人的进度分析报告，先给结论，再写已完成、待解决问题和下一步行动。交付 Word，随后用同一内容源输出 PDF。不得把计划写成已完成。`

附件 `D1-进度资料.txt`：

```text
项目：预约系统试点。日期：2026-10-20。
已完成：预约表单页面、手机号格式校验、预约记录写入接口。
未完成：短信提醒接口；取消预约功能。
测试：已执行 20 条用例，16 条通过，4 条失败。4 条失败中有 3 条与取消预约有关，1 条与重复提交有关。
计划：10 月 28 日前完成取消预约修复；11 月 2 日前完成短信提醒联调。以上两项尚未完成。
风险：短信服务商沙箱账号尚未开通，联调时间可能受影响。
```

重点：数据和状态忠实、16/20 可推导为 80% 且注明口径；Word/PDF 内容一致、PDF 可搜索。

### P1：缺少数值的方案汇报（PPT）

需求：`生成一份 6 页、不带封面的中文 PPT，向学校导师汇报校园预约系统的改进方案。已知问题只有“学生不知道预约状态”和“管理员每周手工导出记录”；建议状态通知和管理端筛选导出。没有用户量、节省时间或预算数据，不要编造统计或效果。重点说明问题、方案、实施顺序、风险和需要导师确认的决定。`

重点：恰好 6 页、每页有清晰结论、用流程/对比等合适版式，不能强行绘制无数据图表。

### P2：有真实数值的汇报（PPT）

需求：`根据附件生成 5 页含封面的中文 PPT，向项目负责人汇报三周缺陷处理进展。至少一页原生可编辑图表，图表只使用附件数值；解释第三周未关闭缺陷增加的原因不能自行猜测，应列为待确认。`

附件 `P2-缺陷记录.txt`：

```text
第 1 周：新增缺陷 12，关闭缺陷 8，周末未关闭缺陷 7。
第 2 周：新增缺陷 9，关闭缺陷 11，周末未关闭缺陷 5。
第 3 周：新增缺陷 14，关闭缺陷 8，周末未关闭缺陷 11。
统计口径：新增和关闭是各周事件数；“周末未关闭”是该周末快照值。未提供缺陷严重程度或原因分类。
```

重点：页数、图表数值和口径准确；没有编造原因；图表和文字布局可读。

### X1：预算表（Excel）

需求：`把附件三条预算记录制作成可编辑 Excel，含预算、实际、差额和执行率原生公式，以及按项目比较预算与实际的原生图表。保留单位“元”，添加汇总行，但图表不要把汇总行混进项目对比。`

附件 `X1-预算记录.txt`：

```text
界面设计：预算 10000 元，实际 9000 元。
后端接口：预算 15000 元，实际 16500 元。
测试验收：预算 8000 元，实际 7200 元。
差额口径：预算减实际；执行率口径：实际除预算。
```

重点：全部三条记录、公式与缓存值、汇总口径、图表排除汇总行、数字类型与单位。

### C1：小型代码项目

需求：`生成可运行的 Python 项目，实现命令行温度换算：输入“25 C”输出“77.0 F”，输入“77 F”输出“25.0 C”。无效格式与不支持的单位返回清楚错误，并以非零状态退出。提供 README 和有实际断言的自动化测试。`

重点：两个方向及错误路径正确，真实运行测试通过；无 Docker 时只能报告未验证，不能以静态语法通过替代运行通过。

## 评分卡

每项 0、1、2 分：0 = 失败或明显缺失；1 = 部分满足但需人工修正；2 = 可以直接使用。记分时写一条具体证据。不可适用写 `N/A`，未验证写 `U`，不能算 2 分。

| 维度 | 2 分的判据 |
| --- | --- |
| 需求满足 | 明确页数、格式、对象、必须内容与禁忌内容全部满足。 |
| 事实忠实 | 数字、状态、原因、来源与素材一致；推断/假设标识清楚。 |
| 内容表达 | 先给结论，段/页有实际信息，结构符合读者用途，无套话填充。 |
| 视觉与可读性 | 全页无截断、拥挤、过小文字或大面积无意义留白；图表传达明确。 |
| 可编辑性 | Word 标题/表格、PPT 图形/图表、Excel 公式等符合需求且为原生对象。 |
| 计算或运行 | 公式/代码在真实运行环境完成验证，结果符合给定输入；不可用时记 `U`。 |
| 协作有效性 | PO、BE、FE、QA、LEAD、SM 的适用职责有可引用产出；交接引用真实内容；QA 与 LEAD 检查最终同一版本。 |

另记：任务路线、六个角色各自的有效贡献、交接次数、拒收/返工原因、QA 与 LEAD 实际检查的文件哈希、总 `passed/failed/unchecked`、页数/字数/图表数、修订轮数、模型调用数、输入/输出 tokens、估算费用、端到端秒数。人工评分时隐藏“改造前/后”版本标签。P1、P2 必须逐页看截图；D1 至少核对首/中/末页；X1 必须打开工作簿核对公式与图表；C1 必须运行两个成功用例和两个错误用例。
