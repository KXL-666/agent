# 第一步：六智能体协作基线报告

## 范围与方法

在未改动生成流程的当前版本，用固定测试集中的 **W1 单页 Word 通知**和 **C1 Python 温度换算项目**各运行一次完整 Sprint。两者分别覆盖文件/内容任务和软件任务；输入与评分卡见 [生成质量基线样本](生成质量基线样本.md)。通过在需求末尾固定添加“请由团队协作完成”，避免当前单文件自动路由直接绕过六人流程。运行时使用已有六名成员的低价模型配置及 `fast=true`，不使用演示回放。

采集脚本为 `scripts/run-quality-baseline.py`。它保存 Sprint ID、路线、任务负责人和最终状态、角色调用数、产物文件哈希、质量检查、事件计数、耗时及 Sprint 持久化的用量估算。完整 JSON 在忽略 Git 的 `backend/workspace/diagnostics/baseline/`，模型密钥和正文不进入报告。除这两次端到端运行外，其余四个固定样本保留到各格式专项与最终对照阶段；**本报告不能代表六个样本的产物质量均已测完**。

### W1：Word 通知

- PO 拆出 4 个任务；BE 接下“大纲”和“Word 排版”，FE 接下“通知正文”，QA 自己接下“内容与格式双人复核”。最后 FE 的正文任务仍为“打回”，其他三项为“待评审”。
- 过程里实际生成 1 份 PRD、3 份 Excel 测试报告和 1 份复盘文档；三份 Excel 的文件级质量报告为 `passed`，但最终 Word 没有生成。这里的 `passed` 只表示对应测试报告文件通过了其检查，不能说明通知成品通过验收。
- PRD 被标记 `failed`，复盘文件也为 `failed`。最终交付记录为 `failed`，没有文件哈希，故 QA/LEAD 不可能已检查最终同一版本。

### C1：Python 项目

- PO 拆出 4 个任务；BE 承担核心换算和 CLI，QA 承担自动化测试，FE 承担 README。最终 README 任务仍为“打回”，其余三项为“待评审”。
- Sprint 工作区留下 8 个任务级代码文件，包含换算模块、CLI 和一个测试文件；没有可下载的最终代码包，也没有完整集成项目的 README。
- 两份 Excel 测试报告的文件级质量报告为 `passed`，第三轮测试产物 `unchecked`；最终交付记录为 `failed`。由于没有最终集成项目，也没有本轮的运行测试证据，功能正确性只能记 `unchecked`，不能由测试报告的文件级 `passed` 推断。

## 协作链的基线判定

| 验收项 | W1 | C1 | 依据 |
| --- | --- | --- | --- |
| PO 提出任务与验收条件 | 已发生 | 已发生 | 两轮均拆出 4 项任务并生成 PRD |
| BE/FE 有可引用的任务贡献 | 部分 | 部分 | 有开发说明或任务级代码，但未形成最终可验收文件 |
| QA 检查最终成品 | 否 | 否 | 两轮均无最终文件 |
| LEAD 独立复核最终成品 | 否 | 否 | 第 5 位角色均 0 次调用；最终文件不存在 |
| SM 发布可追溯成品 | 否 | 否 | 最终记录均为 `failed`，无文件哈希 |
| 六角色交接闭环 | 未通过 | 未通过 | 两轮均不能完成“同一候选文件由 QA 与 LEAD 验收” |

协作闭环通过数为 **0/2**，不是角色评分。由于没有最终成品，不对页面视觉、用户可用性或代码运行正确性给 0～2 分；相应项目记为未验证。这个基线清楚定位了优先修改点：**候选文件应先于 QA/LEAD 产生，失败必须定向返工，并对修订后的同一版本重新验证。**

## 既有格式产物的辅助观察

本机历史中两份已交付 PPT 分别为 9 页、10 页，均无原生图表和图片。它们不是固定 P1/P2 输入，不能用于改造前后的同题评分，只用于确认当前演示文稿版式较单一。

## 可复现方式与证据

```powershell
python scripts/run-quality-baseline.py --case W1
python scripts/run-quality-baseline.py --case C1
```

脚本每次会发起新的真实模型调用，不能用它反复读取旧结果。刷新现有文件哈希和 Sprint 用量可用 `--refresh <现有结果 JSON>`。本次原始记录：

- `backend/workspace/diagnostics/baseline/20261024-030832/W1.json`
- `backend/workspace/diagnostics/baseline/20261024-032244/C1.json`

上述路径是运行期数据，已在工作区忽略范围内；报告中的 Sprint ID 可在应用历史中检索。开始第二步时，以这两个样本检查 PO 需求契约和交接记录是否让各角色的实际贡献可追溯。完成整个改造后，必须对 [六个固定样本](生成质量基线样本.md)全部复跑并人工核对真实文件。
